# Real-Time Machine Learning Based Fraud Detection and Transaction Monitoring System

## 1. Project Overview

This locally runnable college demonstration scores synthetic transactions with a trained Random Forest model, converts each model probability into an approval/review/block decision, and records the result in SQLite. The dashboard presents current counts, a decision chart, model evaluation metrics, and recent activity.

This is an educational simulation. It does not identify real fraud or determine whether a real person is committing a crime.

## 2. Features

- Responsive transaction-monitoring dashboard with live refresh.
- Validated transaction analysis and a unique transaction ID per request.
- Approved, review, and blocked decisions based on model probability thresholds.
- Safe, suspicious, and high-risk sample transactions for demonstrations.
- Persistent SQLite transaction history and aggregate dashboard statistics.
- Model holdout metrics, including a confusion matrix.
- Excel-compatible CSV export, browser print-to-PDF, and confirmed history clearing.

## 3. Technologies

- Python 3.11 or newer, FastAPI, Uvicorn, and Pydantic.
- Scikit-learn, Pandas, NumPy, and Joblib.
- SQLite via Python's standard library.
- HTML, CSS, JavaScript, and Chart.js from its CDN.

## 4. ML Workflow

`generate_dataset.py` creates reproducible synthetic examples and probabilistic fraud labels with interaction effects. `train_model.py` makes a stratified 80/20 train/test split, fits a RandomForestClassifier, calculates accuracy, precision, recall, F1-score, and a confusion matrix, then saves the model and evaluation details together in a Joblib artifact. The API loads that artifact and calls `predict_proba`; the application applies business decision thresholds after scoring.

## 5. Dataset

The generator writes 12,000 synthetic rows to `data/transactions.csv`. Features are amount, hour, new-device indicator, inferred location-change indicator, transaction count and spending in the last five minutes, average prior transaction amount, and distance from the usual location. Labels are probabilistic and include noisy feature interactions so that one signal alone does not guarantee a fraud label. All records are artificial.

The browser collects a device ID for display and persistence, but it is not included in the model feature set. `location_change` is derived from distance (100 km or more); the raw location name is not sent to the classifier.

## 6. Model Training

Training uses a fixed random seed for repeatable data and split results. The model artifact is `model/fraud_model.joblib`; it contains the fitted classifier, ordered feature names, training row count, and holdout metrics. Re-run the generator and trainer whenever the synthetic data or model settings change.

## 7. Real-Time Prediction

The browser posts validated JSON to `POST /api/predict`. The API extracts model features, obtains the probability for the fraud class, applies the following business rules, saves the transaction, and returns its result:

| Fraud probability | Decision | Risk | Status |
| --- | --- | --- | --- |
| Below 30% | APPROVED | LOW | SUCCESS |
| 30% through 70% | REVIEW | MEDIUM | PENDING |
| Above 70% | BLOCKED | HIGH | DECLINED |

The percentage is generated by the trained classifier, not a fixed example value.

## 8. Database

SQLite initializes `database/transactions.db` when the FastAPI application starts. Each analyzed transaction records its input fields, model probability, risk, decision, status, and UTC creation time. The database file is created locally on first run.

## 9. API

- `GET /` serves the dashboard.
- `POST /api/predict` validates, scores, stores, and returns a transaction.
- `GET /api/transactions?limit=20` returns recent transactions (limit 1–200).
- `DELETE /api/transactions` permanently clears all saved transaction history.
- `GET /api/stats` returns totals by decision and average model probability.
- `GET /api/model-metrics` returns holdout metrics and model metadata.

## 10. Installation

Open this folder directly in VS Code. In its terminal, use these Windows commands:

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

Python 3.11 or newer is required. In PowerShell, if script activation is restricted, use `venv\Scripts\Activate.ps1` or run the commands through Command Prompt.

## 11. Running the Project

Run these commands from the opened project folder, in order:

```powershell
python generate_dataset.py
python train_model.py
uvicorn app:app --reload
```

Open [http://127.0.0.1:8000](http://127.0.0.1:8000). API documentation is available at [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

## 12. Demo Instructions

1. Generate the dataset, train the model, and start the API as above.
2. Open the dashboard and show the training metrics and initially empty transaction monitor.
3. Choose **Safe**, **Suspicious**, or **High risk** to load a complete sample, then select **ANALYZE TRANSACTION**.
4. Discuss the model-derived probability and the corresponding decision, risk, and status.
5. Show how the counters, chart, and transaction table update, then try the other samples.
6. Use **Excel CSV** to download the full transaction history, or **PDF / Print** and choose **Save as PDF** in the browser print dialog.
7. **Clear history** removes saved transactions only after browser confirmation; it does not remove the dataset or trained model.

The sample values illustrate different risk patterns; model output is learned from synthetic data and is not promised to produce a particular percentage for any sample.

## 13. Limitations

- Synthetic examples cannot represent the complexity, drift, or quality issues of real payment data.
- The model's metrics describe a generated holdout set and do not establish real-world performance.
- Location change is approximated from the entered distance; the location name itself is not geocoded.
- This demo has no authentication, production observability, or protection for deployment on a public network. Keep it local and use no real personal or payment data.
- Chart.js and web fonts use external CDNs; the dashboard's core form and API do not require a cloud service.

## 14. Future Improvements

- Evaluate on approved, privacy-reviewed, representative data and monitor calibration and drift.
- Add authentication, role-based access, audit controls, retention policies, and secure deployment practices.
